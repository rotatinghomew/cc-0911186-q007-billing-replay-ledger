# 资源用量日结宽表的重复事件抵扣、核对与调整账本

多采集器资源用量的日结、去重、核对、关账调整和月度汇总基线。

仓库内的实现使用 Python 3.11 标准库和 SQLite，数据只写入命令行指定的本地数据库及导出目录。`lakeapp.storage` 保存原始接收、事件身份、计费事实、冲突、账单、调整和版本清单；`lakeapp.contract` 负责输入约定与事件指纹；`lakeapp.ingest` 接收来源批次并登记送达；`lakeapp.derive` 负责归并计费事实；`lakeapp.billing` 负责账单、核对、调整账本与汇总；`lakeapp.publish` 读取并写出可追溯版本；`lakeapp.cli` 提供本地操作入口。

## 运行

在 Python 3.11 环境中执行 `python3 -m unittest discover -s tests -v` 运行测试，执行 `python3 -m compileall -q lakeapp tests` 检查构建和语法。示例数据是本地合成记录，不依赖外部服务或联网。

## 计费归并规则

- **事件身份**：对读数内容（来源、业务键、事件类型、数值、发生时间）计算 SHA-256 指纹 `event_id`。同一读数内容无论由哪个采集批次送达、重送多少次，指纹相同，归并时保持幂等，不重复计费。
- **采集批次**：每次送达登记到 `event_deliveries`（事件身份 + 批次），批次重放只产生一条送达记录；原始读数在 `raw_events` 中按事件身份去重保存，并附全部送达批次，供复核追溯。
- **同键异内容**：业务键与业务日期相同但事件身份不同的记录不覆盖当前计费量，而是进入 `fact_conflicts` 标记为“待核对”，事实状态同步变为待核对。核对采纳且账单开放时才重新计算事实；核对驳回则保留原值。
- **撤回（retract）**：账单开放时撤回同业务日期的事实（同键跨日时回退到最近一条事实）；账单关闭后撤回只能作为候选，核对后转调整，原日结结果不删除。

## 账单与调整

- 账单按业务日期关闭。存在待核对冲突时拒绝关账，必须先完成核对；关账后 `billing_facts` 冻结为“已关闭”。
- 关账后到达的任何更正（含新读数、改值、撤回）只登记冲突，核对采纳后写入 `adjustments`：记录原事件身份、调整事件身份、来源批次、原值、调整值、差额和人工缘由，原日结事实保持不变；差额为零不产生调整行。
- 关账后同一读数内容的重送仍是静默幂等，不产生冲突和调整。

## 复核与月度汇总

- `review_rows` 把原始读数、送达批次、去重后计费量、事实状态、账单状态和调整缘由对齐到同一视图。
- `monthly_summary(month)` 按租户分列原始结算（`original_settlement`）、调整笔数与调整差额（`adjustment_delta`），并给出最终金额 `final_amount = 原始结算 + 调整差额`，财务可逐笔解释租户看到的金额变化。

## 现有契约

输入批次包含来源名、批次标识、游标和记录数组。原始批次以 JSON 保存，重复批次不会再次产生事实。事实查询按业务日期和版本清单读取，清单包含行数与行内容 SHA-256 摘要，用于发现导出内容被替换。数据库初始化由运行入口完成，已有数据不会因重新打开而丢失。

## 目录职责

`lakeapp/storage.py` 负责事务和表结构，`lakeapp/contract.py` 负责记录约束与事件身份，`lakeapp/ingest.py` 负责接收、送达登记和来源进度，`lakeapp/derive.py` 负责从原始读数归并计费事实与冲突，`lakeapp/billing.py` 负责关账、核对决策、调整账本、复核视图和月度汇总，`lakeapp/publish.py` 负责版本清单与回读，`lakeapp/cli.py` 负责把这些业务操作组合给本地使用者。测试数据覆盖幂等重送、同键异内容核对、关账前后更正、调整账本与月度汇总。

## CLI 操作

`receive`（接收并归并）、`facts`（计费事实）、`raw-events`（去重原始读数与送达批次）、`conflicts`（冲突队列）、`close-bill`（关账）、`resolve`（核对决策，需缘由）、`adjustments`（调整账本）、`monthly`（月度汇总）、`review`（复核视图）、`progress`、`publish`、`read`。
